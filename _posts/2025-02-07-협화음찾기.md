## 1. 서론

‘하모니아’는 노래에 어울리는 화음을 찾아주는 서비스다. 사용자에게 음악적 영감을 제공하고 화음을 쌓는 과정을 돕는 것을 목표로 하며, 원하는 노래에 어울리는 화음을 찾아주는 기능을 제공한다.

## 2. 문제 인식

### 2.1. 주제 선정 과정

다음 네 가지 주제를 구현 가능성, 필요성, 창의성을 기준으로 평가했다.

1. 교내 팀 프로젝트 매칭 사이트
2. 협화음을 찾아주는 프로젝트
3. 카메라로 대상을 인식하여 분리수거 방법을 알려주는 앱
4. 교내 도서관 분리수거 개선 프로젝트

### 2.2. 주제 평가 및 비교

**교내 팀 프로젝트 매칭 서비스**의 구현 가능성은 2점으로 평가했다. 취업이나 학업 매칭과 같은 기존 서비스를 응용하면 교내 팀 매칭 서비스를 만들 수 있다고 판단했기 때문이다. 많은 학생이 프로젝트나 대회에서 적합한 팀원을 구하는 데 어려움을 겪고 있으므로 필요성은 3점으로 평가했다. 다만 이미 존재하는 매칭 서비스와 비슷한 점이 많아 창의성은 1점으로 평가했다.

**협화음을 찾아주는 서비스**의 구현 가능성은 3점으로 평가했다. 음성 처리 기술과 음악 생성 프로그램 등 관련 기술이 잘 발달해 있어 이를 활용하면 협화음을 자동으로 만드는 프로그램을 충분히 개발할 수 있기 때문이다. 전문 음악가나 취미로 음악을 만드는 사람에게는 유용하지만 모든 사람에게 필요한 서비스는 아니므로 필요성은 2점으로 평가했다. 화음을 자동으로 만드는 아이디어가 독창적이고 사전 조사에서 비슷한 서비스를 찾지 못했기 때문에 창의성은 3점으로 평가했다.

**카메라로 분리수거 대상과 방법을 알려주는 서비스**의 구현 가능성과 필요성은 각각 1점으로 평가했다. 물체 인식 기술과 분리수거 정보를 제공하는 데이터베이스가 필요해 주어진 시간 안에 구현하기 어렵고, 관련 정보를 인터넷이나 지역 시설에서 쉽게 찾을 수 있기 때문이다. 환경 문제를 해결하려는 접근에는 의미가 있지만 물체 인식 기술이 이미 여러 분야에서 사용되고 있어 창의성은 2점으로 평가했다.

**도서관 분리수거 개선 서비스**의 구현 가능성과 필요성, 창의성은 각각 2점으로 평가했다. 구체적인 방법을 정하면 구현은 어렵지 않지만, 다른 환경 개선 문제와 비교하면 중요도가 상대적으로 낮다고 판단했다. 실용적인 아이디어이지만 기존 문제를 개선하는 수준이고 만족스러운 개선안이 떠오르지 않았다는 점도 반영했다.

최종 평가 순위는 협화음 찾기, 팀 매칭, 도서관 분리수거, 카메라 분리수거 순이었다. 높은 창의성과 구현 가능성을 근거로 협화음을 찾아주는 프로젝트를 최종 주제로 선정했다.

## 3. 문제 정의

### 3.1. 인터뷰를 통한 사용자 요구 파악

서비스의 주요 기능을 구상하기 위해 사용자 인터뷰를 진행했다. 화음을 넣을 때 겪는 어려움을 묻자, 화음을 부르다가 어느 순간 원래 멜로디를 부르게 되어 어렵다는 답변이 나왔다. 화음을 잘 넣지 않는 이유에 대해서는 노래를 매우 잘하지 않는 이상 화음을 맞추기 쉽지 않으며, 단순한 노래 실력보다 음에 대한 감각이 더 중요하다는 의견이 있었다. 이를 통해 화음을 잘 넣으려면 노래 실력을 넘어선 감각과 재능이 필요하다는 인식이 있음을 확인했다.

원하는 노래에 맞는 화음을 악보와 음성 중 어떤 방식으로 제공할지도 질문했다. 인터뷰 대상자는 모두 음성을 선호했다. 음성이 따라 하기 편하고, 절대음감이 아니라면 악보만 보고 화음을 파악하기 어려우며, 악보를 잘 읽지 못하는 사람도 있기 때문이다.

## 4. 아이디어 도출 및 평가

### 4.1. 사용자 인터뷰 분석

인터뷰를 바탕으로 “노래에 화음을 넣어 부르고 싶지만 조화로운 화음을 찾기 어렵다”는 문제를 정의했다.

### 4.2. 문제의 근본 원인 분석

근본 원인을 찾기 위해 ‘왜?’라는 질문을 반복했다.

- **왜 화음을 넣는 것이 어려운가?** 한 멜로디에 어울리는 화음이 무엇인지 모른다.
- **왜 어울리는 화음이 무엇인지 모르는가?** 음에 대한 감각이 부족하다.
- **왜 감각이 부족한가?** 음에 대한 감각을 늘리기 쉽지 않다.
- **왜 감각을 늘리기 어려운가?** 스스로 연습하기 어렵다.
- **왜 연습하기 어려운가?** 연습을 돕는 플랫폼이 부족하다.

처음 정의한 “화음을 잘 넣고 싶지만 어울리는 화음을 찾기 어렵다”는 문제에서 출발해 “이를 해결하기 위한 연습 플랫폼이 필요하다”는 결론을 도출했다.

### 4.3. 관련 지식재산권 조사

## 5. 프로토타입 제작 및 테스트

### 5.1. 앱 시연

앱 이름은 ‘하모니아(Harmonia)’이며, 화음을 뜻하는 ‘Harmony’에서 유래했다. 이름을 직관적으로 지어 사용자가 화음과 관련된 앱이라는 점을 한눈에 알 수 있도록 했다.

보컬이 포함된 원곡 음원 파일 대부분은 음원 저작권을 비롯해 공연권, 실연자권, 음반 제작자권 등의 보호를 받는다. 서비스가 이 음원을 활용해 화음을 추가하거나 피치를 변환하면 저작권법상 2차적 저작물을 작성하는 행위로 간주될 여지가 있다. 따라서 사용자는 음원 파일이 아니라 직접 녹음한 목소리 파일만 업로드하여 화음을 추출할 수 있다.

화음 생성 코드는 구현했지만 앱을 직접 개발하는 대신 Figma로 프로토타입을 제작했다. 하모니아 앱의 화면 흐름은 다음과 같다.

1. **첫 실행 화면:** 로그인 또는 회원가입 버튼을 제공한다.
2. **로그인 화면:** 이메일과 비밀번호로 로그인할 수 있다.
3. **시작 화면:** 로그인 후 `Start` 버튼을 눌러 서비스를 시작한다.
4. **파일 업로드 및 히스토리:** 자신의 목소리가 담긴 파일을 업로드하고, 지금까지 추출한 화음 파일을 `History`에서 확인한다. 업로드 파일은 MR과 에코가 없는 생목소리여야 한다. 음원 파일을 넣으면 앱이 이를 인식하여 업로드에 실패한다.
5. **화음 선택 화면:** 원곡을 기준으로 몇 반음을 올리거나 내릴지 선택한다. 예를 들어 `-1`은 원곡보다 1반음 낮추고, `2`는 2반음 높인다.
6. **로딩 화면:** 화음을 생성하고 있음을 사용자에게 알린다.
7. **화음 파일 선택:** 업로드한 파일과 화음을 합친 `mixed` 파일을 출력할지, 화음 파일만 단독으로 추출할지 선택한다. 결과가 마음에 들지 않으면 `Change Chord!` 버튼으로 화음을 다시 선택한다.
8. **결과 파일 형식 선택:** 결과를 WAV와 MP3 중 어떤 형식으로 받을지 선택한다. WAV는 MP3보다 음질 손상이 적지만 파일 용량이 크다.
9. **히스토리 화면:** 지금까지 추출한 화음을 들어볼 수 있다. 화음 연습을 돕는 앱인 만큼 결과 파일은 자동으로 저장되며 제목과 썸네일 이미지를 지정할 수 있다.
10. **공유 기능:** 더 나은 화음을 만들 수 있도록 사용자가 추출한 화음을 다른 사람과 공유한다. 음원 파일 업로드를 금지한 이유 중 하나는 공유 과정에서 발생할 수 있는 저작권 문제다.

### 5.2. 화음 생성 구현

처음 구상한 화음 생성 과정은 다음과 같다.

1. 원곡 파일에서 조성과 코드 진행을 파악한다.
2. 보컬 파일에서 피치를 추출한다.
3. 피치를 분석하여 음을 기준으로 분리한다.
4. 각 음에 적용할 화음의 음 간격을 결정한다.
5. 피치를 조절하여 화음을 생성한다.
6. 생성한 화음을 원곡에 믹싱한다.
7. 화음이 추가된 최종 파일과 화음 파일을 저장한다.

이 과정에 따라 코드를 작성했지만 여러 문제가 발생했다. 각 음에 어떤 화음을 넣어야 하는지 명확히 결정하기 어려웠고, 이론적으로 음을 맞춰 생성해도 실제로 들었을 때 어색한 경우가 있었다. 음을 기준으로 음성을 분리하자 구간이 지나치게 많아져 각 구간의 피치를 조절하는 데도 많은 시간이 걸렸다.

음을 기준으로 나누는 대신 프레임 단위로 처리하는 방식도 시도했지만, 화음이 부정확하고 프레임마다 소리가 끊겨 듣기 불편한 결과가 생성되었다. 여러 시행착오 끝에 음마다 화음을 결정하기보다는 전체 피치를 조절하는 방식이 최선이라고 판단했다.

최종 구현에는 `librosa`, `pydub`, `NumPy`를 사용했다.

```python
from google.colab import drive
import os

import librosa
import numpy as np
from pydub import AudioSegment

# 1. Google Drive 마운트

# 2. 출력 폴더 지정 및 생성
save_folder = "/content/drive/MyDrive/Processed_Audio"
if not os.path.exists(save_folder):
    os.makedirs(save_folder)
    print(f"폴더 생성 완료: {save_folder}")
else:
    print(f"폴더가 이미 존재합니다: {save_folder}")

# 3. 오디오 파일 로드
input_file = (
    '/content/drive/MyDrive/ColabNotebooks/'
    '1_1_1_거리에서---성시경_(Vocals)_(Vocals)_(No Reverb).wav'
)

try:
    y, sr = librosa.load(input_file, sr=None)
    print(f"오디오 파일 '{input_file}' 로드 성공! 샘플링 레이트: {sr}Hz")
except Exception as e:
    print(f"오디오 파일 로드 중 오류 발생: {e}")
    raise

# 4. 피치 시프팅을 통한 하모니 생성
try:
    n_steps = int(input())  # 반음 단위 이동: 양수는 위, 음수는 아래
    harmony_y = librosa.effects.pitch_shift(y=y, sr=sr, n_steps=n_steps)
    print("피치 시프팅 성공: 하모니 생성 완료!")
except Exception as e:
    print(f"피치 시프팅 중 오류 발생: {e}")
    harmony_y = None

# 5. 16비트 PCM 변환 함수
def to_16bit_pcm(audio):
    """오디오 데이터를 16비트 PCM 형식으로 변환한다."""
    max_int16 = np.iinfo(np.int16).max
    return (audio * max_int16).astype(np.int16)


# 6. NumPy 배열을 16비트 PCM 형식으로 변환
y_pcm = to_16bit_pcm(y)
if harmony_y is not None:
    try:
        harmony_y_pcm = to_16bit_pcm(harmony_y)
    except Exception as e:
        print(f"PCM 변환 중 오류 발생: {e}")
        raise
else:
    print("하모니 생성 실패: 원본 오디오만 처리됩니다.")
    harmony_y_pcm = None

# 7. AudioSegment 변환 및 믹싱
try:
    original = AudioSegment(
        y_pcm.tobytes(),
        frame_rate=sr,
        sample_width=y_pcm.dtype.itemsize,
        channels=1,
    )

    if harmony_y_pcm is not None:
        harmony = AudioSegment(
            harmony_y_pcm.tobytes(),
            frame_rate=sr,
            sample_width=harmony_y_pcm.dtype.itemsize,
            channels=1,
        )
        mixed = original.overlay(harmony)
    else:
        mixed = original
except Exception as e:
    print(f"AudioSegment 변환 중 오류 발생: {e}")
    raise

# 8. 결과 저장
try:
    harmony_mp3_path = os.path.join(save_folder, "harmony.mp3")
    harmony_wav_path = os.path.join(save_folder, "harmony.wav")
    mixed_mp3_path = os.path.join(save_folder, "final_mix.mp3")
    mixed_wav_path = os.path.join(save_folder, "final_mix.wav")

    if harmony_y_pcm is not None:
        harmony.export(harmony_mp3_path, format="mp3")
        harmony.export(harmony_wav_path, format="wav")
        print(
            f"하모니 오디오가 저장되었습니다:\n"
            f"MP3: {harmony_mp3_path}\nWAV: {harmony_wav_path}"
        )

    mixed.export(mixed_mp3_path, format="mp3")
    mixed.export(mixed_wav_path, format="wav")
    print(
        f"하모니가 추가된 오디오가 저장되었습니다:\n"
        f"MP3: {mixed_mp3_path}\nWAV: {mixed_wav_path}"
    )
except Exception as e:
    print(f"오디오 저장 중 오류 발생: {e}")
```

코드는 다음 순서로 동작한다.

1. `librosa`로 보컬 파일을 불러온다.
2. `librosa`의 피치 시프팅 함수를 사용하여 피치를 `n`반음 조절하고 화음을 생성한다.
3. 불러온 오디오 데이터를 16비트 PCM 형식으로 변환한다.
4. 변환한 PCM 데이터로 `pydub.AudioSegment` 객체를 생성한다.
5. 원본 오디오 위에 하모니 오디오를 오버레이하여 원본 보컬에 화음을 믹싱한다.
6. 완성된 최종 파일과 화음 파일을 저장한다.

### 5.3. 프로토타입의 한계

1. **화음의 단조로움:** 원곡 전체를 그대로 올리거나 내려 화음을 생성하므로, 원곡의 조성을 따르지 않는 화음이나 아카펠라처럼 원곡과 박자를 달리하는 화음을 만들 수 없다.
2. **화음의 어색함:** 이론적으로 듣기 좋은 화음과 실제로 듣기 좋은 화음이 다를 수 있어 중간에 어색하게 느껴지는 모든 화음을 수정하기 어렵다.
3. **편의성 문제:** 사용자는 화음을 실시간으로 듣고 다른 화음과 비교하며 선택해야 한다. 그러나 프로토타입에서는 화음을 바꿀 때마다 처음부터 파일을 다시 업로드하고 기다려야 하므로 시간이 오래 걸린다.

### 5.4. 개선 방안

제작 과정에서 확인한 한계를 보완하기 위해 두 가지 방법을 구상했다.

**악보와 목소리 파형 활용:** 사용자가 목소리 파일을 업로드하면 주파수를 분석하여 악보와 목소리 파형을 추출한다. 기본적으로 프로토타입과 같이 원하는 반음의 크기만큼 피치를 올리거나 내린다. 악보에서는 사용자가 결과를 실시간으로 들으며 어색한 화음을 음표 단위로 바꾸고, 파형에서는 원하는 구간을 선택하여 서로 다른 화음을 설정한다. 이 기능을 추가하면 화음의 어색함과 편의성 문제를 해결할 수 있다.

**생성형 AI 활용:** 음악 생성 AI인 SUNO에서 얻은 아이디어다. SUNO에 화음 생성 전용 기능은 없지만, 생성한 음악에 포함된 일부 화음은 조화롭게 들린다. 따라서 잘 훈련된 AI 모델을 활용하면 조화로운 화음을 만들 수 있다. 사용자는 프롬프트에 화음에 대한 요구 사항을 입력하고, AI는 이에 맞는 화음을 생성한다. 목소리를 변형하여 마치 남녀가 듀엣하는 듯한 화음 파일을 생성하는 기능도 추가할 수 있다. 사용자가 직접 들으면서 화음을 지정할 수는 없지만 앞서 확인한 한계를 대부분 해결할 수 있다.
